# 更新日志生成器（Changelog Generator）

本技能可将技术性的 Git 提交信息转化为经过润色、用户友好的更新日志，让您的客户和用户真正理解并欣赏产品的新变化。

## 何时使用此技能

- 为新版本准备发布说明  
- 创建每周或每月的产品更新摘要  
- 向客户说明产品变更  
- 为应用商店提交撰写更新日志条目  
- 生成产品更新通知  
- 编写内部发布文档  
- 维护公开的产品更新页面或变更日志  

## 此技能的功能

1. **扫描 Git 历史**：分析特定时间段内或两个版本之间的提交记录  
2. **分类变更内容**：将提交归类为逻辑清晰的类别（新功能、改进、错误修复、破坏性变更、安全更新等）  
3. **技术语言 → 用户语言**：将开发者提交信息转化为客户能理解的语言  
4. **专业格式化**：生成结构清晰、排版整洁的更新日志条目  
5. **过滤噪音信息**：自动排除内部提交（如代码重构、测试等）  
6. **遵循最佳实践**：应用通用的更新日志规范，并支持您自定义的品牌语调  

## 使用方法

### 基础用法

在您的项目仓库中执行以下指令：

```
创建自上一版本以来的更新日志
```

```
生成过去一周所有提交的更新日志
```

```
为 2.5.0 版本创建发布说明
```

### 指定日期范围

```
创建 3 月 1 日至 3 月 15 日之间所有提交的更新日志
```

### 使用自定义规范

```
基于自 v2.4.0 以来的提交创建更新日志，并使用我提供的 CHANGELOG_STYLE.md 中的格式规范
```

## 示例

**用户输入**：“创建过去 7 天提交的更新日志”

**输出结果**：
```markdown

## ✨ 新功能

- **团队工作区**：为不同项目创建独立的工作区。邀请团队成员加入，让一切井然有序。

- **快捷键支持**：按下 ? 键即可查看所有可用快捷键，无需鼠标即可快速导航。

## 🔧 改进

## 🐛 问题修复

- 修复了大尺寸图片无法上传的问题
```

**灵感来源**：Manik Aggarwal 在 Lenny's Newsletter 中分享的使用场景

## 使用技巧

- 请在 Git 仓库根目录下运行  
- 指定日期范围可生成更有针对性的更新日志  
- 使用 `CHANGELOG_STYLE.md` 文件确保格式风格统一  
- 发布前请务必审阅并适当调整生成的内容  
- 可直接将输出保存至 `CHANGELOG.md` 文件  

## 相关应用场景

- 制作社交媒体上的产品公告文案
